# 언어 공통 작업 기준

## 적용 범위
- 프로젝트의 `CLAUDE.md`, formatter, linter, compiler, test 설정이 있으면 그 기준을 우선한다.
- 여러 언어가 함께 바뀌면 각 언어 기준을 해당 파일에만 적용하고, 공통 변경 판단은 현재 프로젝트 관례를 우선한다.

## 공통 기준
- 공개 API, exported type, 컴포넌트 props, 직렬화 형태 변경은 호출부·테스트·문서 영향을 함께 확인한다.
- 오류, null, 비동기, 취소, 리소스 소유권처럼 빠뜨리면 결함으로 이어지는 경계를 우선 확인한다.
- 리뷰 의견은 수정 가능한 구체 지점에 연결하고, 선호 차이만 있는 의견은 실제 유지보수 위험이 있을 때만 남긴다.

## 주석 작성 기준
- 단순 유틸이나 값을 그대로 넘기는 위임에는 주석을 뺀다.
- 무엇을 하는지는 코드로 읽히지만 왜 그렇게 했는지는 읽히지 않는 자리에 주석을 남긴다 — 코드로 드러나지 않는 제약,
  외부 시스템의 뜻밖의 동작, 예외적인 변환, 실패로 끊을지 기본값으로 넘길지처럼 바꾸면 깨지는 선택. 해당 코드 바로 옆에 둔다.
- 그런 자리는 함수가 짧거나 주변 코드에 주석이 없다는 이유로 건너뛰지 않는다.
- 주석 하나는 제약 하나를 1~2줄로 설명한다. 배경 이야기·다른 구현 비교·코드 다시 쓰기로 늘리지 않는다.
- 심볼 위 doc 주석은 역할·계약 요약만 담고, 실행 흐름·검증 절차는 해당 단계 코드 옆에 둔다.
  본문을 읽으면 그대로 보이는 분기·기본값은 doc 주석에 다시 적지 않는다.
- 여러 멤버에 공통인 배경은 멤버마다 되풀이하지 말고 경계(타입·패키지)로 모으되, 다른 심볼·패키지가 가진 동작까지 끌어와 적지 않는다.
- 변경 경위·구현 순서·계획 식별자·계획 문서 본문 옮겨 적기 같은 작업 과정 기록은 주석으로 남기지 않는다.
- 구조·형식은 언어·프로젝트 관례를, 주석 언어는 `CLAUDE.md` §언어를 따른다.
- 로직이 바뀌면 관련 주석도 같은 응답에서 고치거나 지운다.
