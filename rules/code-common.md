# 언어 공통 작업 기준

## 적용 범위
- 프로젝트의 `CLAUDE.md`, formatter, linter, compiler, test 설정이 있으면 그 기준을 우선한다.
- 여러 언어가 함께 바뀌면 각 언어 기준을 해당 파일에만 적용하고, 공통 변경 판단은 현재 프로젝트 관례를 우선한다.

## 공통 기준
- 공개 API, exported type, 컴포넌트 props, 직렬화 형태 변경은 호출부·테스트·문서 영향을 함께 확인한다.
- 오류, null, 비동기, 취소, 리소스 소유권처럼 빠뜨리면 결함으로 이어지는 경계를 우선 확인한다.
- 리뷰 의견은 수정 가능한 구체 지점에 연결하고, 선호 차이만 있는 의견은 실제 유지보수 위험이 있을 때만 남긴다.

## 주석 작성 기준
- 이름과 시그니처로 뜻이 드러나는 코드에는 주석을 남기지 않는다.
- 주석은 설명하는 코드 바로 옆에 적는다.
- 변경 경위·계획 식별자 같은 작업 과정 기록은 남기지 않고, 로직이 바뀌면 관련 주석도 같은 응답에서 고치거나 지운다.
