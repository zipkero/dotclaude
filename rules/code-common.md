# 언어 공통 작업 기준

## 공통 기준
- 공개 API, exported type, 컴포넌트 props, 직렬화 형태를 바꾸면 호출부·테스트·문서에 미치는 영향을 같이 본다.
- 오류, null, 비동기, 취소, 리소스 해제처럼 놓치면 버그가 되는 부분을 먼저 보되, 검사는 외부 입력과 실패할 수 있는 호출에만 둔다.

## 주석
- 주석은 자연스러운 한국어로 쓰고, 그 파일이나 디렉토리가 영어 주석을 쓰면 따른다.
- 문서화 주석은 한 줄로, 이름과 시그니처만으로 알 수 없는 것만 적는다.
- 일반 주석은 코드만 봐서는 모르고 어기면 동작이 깨지는 제약만, 그 제약을 만드는 쪽과 어겼을 때의 증상을 함께 적는다.
- 코드를 다시 말하는 주석, 단계 표시, 변경 경위는 쓰지 않는다.
- 코드를 고치면 근처 주석이 아직 맞는지 보고, 틀리면 고치거나 지운다.
